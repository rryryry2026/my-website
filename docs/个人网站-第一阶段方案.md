# 晚巷 · 个人网站第一阶段方案

> 文档版本：v1.0  
> 编写日期：2026-11-03  
> 当前状态：V1 基线已实现，待个人信息与上线配置确认  
> 关联项目：`E:\个人博客`

## 1. 项目概述

### 1.1 项目定位

「晚巷」是一个以黄昏、旧巷和安静的日常为底色的个人博客。

视觉母题来自小说《我的郁金香小姐》中的「肖艾」：屋顶、晚风、旧砖墙、落日和一点不急着发生的故事。网站不复刻具体剧情，而是借用这些意象，建立一个温暖、静谧、有烟火气的个人表达空间。

第一阶段不做完整内容平台，只做一件事：**让访客舒服地读到文字，让站长轻松地继续写。**

### 1.2 第一阶段目标

1. 建立清晰、有辨识度的个人博客视觉形象。
2. 完成首页、文章列表、文章详情、随笔 / 摄影、关于页和 404 页。
3. 支持本地 Markdown 自动生成文章列表与详情页。
4. 实现全屏黄昏视频背景与完整的移动端 / 省电兜底。
5. 保证桌面端、移动端均可顺畅阅读。
6. 输出可直接部署到阿里云 Nginx 的静态 `dist/`。
7. 建立后续迭代可复用的技术结构与内容规范。

### 1.3 第一阶段的成功标准

- 访客进入首页后，能在 3 秒内理解网站的气质与主要内容。
- 从首页到达任意一篇文章，不超过 2 次点击。
- 新增文章只需要添加一个 Markdown 文件，不需要改页面代码。
- 在手机端仍能清楚阅读，且不会因为背景视频产生明显流量负担。
- 页面不使用外部字体、CDN 或框架运行时。
- 构建结果完整、可迁移、可长期托管。

### 2.2 本期不包含

以下内容明确留到后续阶段，避免第一阶段范围膨胀：

- 评论区、点赞、登录或用户系统
- 后台 CMS 或在线编辑器
- 站内搜索、标签归档页
- 数据统计、埋点与用户画像
- 多语言
- 服务端渲染、数据库或 API 服务
- RSS、站点地图（可作为第二阶段优先项）
- 复杂的照片相册、灯箱和原图下载
- 深色 / 浅色主题切换
- 第三方字体、CDN 依赖

### 2.3 设计原则

1. **安静优先**：页面不争抢注意力，背景负责氛围，文字负责内容。
2. **可读性高于炫技**：毛玻璃、视频、动效都必须为阅读服务。
3. **少而完整**：页面数量不多，但每个页面都完成导航、间距、空状态和移动端适配。
4. **慢更新友好**：不依赖后台和构建服务，本地写 Markdown 即可更新。
5. **有节制地浪漫**：引文、郁金香、黄昏意象应作为细节出现，而不是堆砌元素。

## 3. 视觉方案

### 3.1 核心意象

- **时间**：黄昏、落日余温、灯刚刚亮起的时刻
- **空间**：旧砖墙、屋檐、小巷、半开的窗
- **人物**：坐在墙头看晚霞的少女，抱着吉他的背影
- **情绪**：温暖、安静、怀旧、不催促

### 3.2 色彩系统

| 角色 | 色值 | 使用场景 |
| --- | --- | --- |
| 夕阳橙 | `#FF6B35` | 主按钮、强调文字、阅读进度、播放控件 |
| 琥珀金 | `#F3C581` | 英文小标题、图标、辅助点缀 |
| 深砖红 | `#8F3E2F` | 背景装饰、暖色过渡 |
| 深棕黑 | `#1A0B07` | 页面底色、遮罩与深色卡片 |
| 暖米白 | `#FFF2DF` | 正文标题、主文字 |
| 半透明暖白 | `rgba(255, 232, 210, 0.7)` | 次级说明文字 |
| 玻璃描边 | `rgba(255, 211, 169, 0.14)` | 卡片边框、分割线 |

整体保持低饱和暖色，不使用纯黑、纯白和冷色高光。

### 3.3 字体系统

- 标题、引文、文章大标题：宋体 / 思源宋体 / 楷体回退栈，强调文学感。
- 正文、导航、元信息：系统无衬线中文字体，保证屏幕阅读舒适度。
- 英文小标题使用大写和较大的字间距，承担节奏和仪式感。
- 不引入外部字体，避免国内网络环境下的字体下载失败与布局偏移。

### 3.4 材质语言

- 毛玻璃卡片：半透明深棕底 + `backdrop-filter: blur(18–24px)`。
- 细描边：暖白 12%—24% 透明度，避免生硬。
- 内高光：卡片顶部增加 1px 暖白高光，模拟亚克力边缘。
- 投影：大范围、低不透明度的深色柔和阴影，不使用硬阴影。
- 纸张感元素：首页明信片使用暖色半透明纸张 + 胶带细节，和玻璃卡片形成对比。

### 3.5 动效原则

- 页面进入：标题、介绍、卡片按 80—150ms 间距依次淡入上移。
- 交互反馈：卡片悬浮 4—5px，箭头缓动，时长 300—500ms。
- 背景音乐：只在播放时旋转黑胶，并显示呼吸环。
- 阅读辅助：阅读进度条随页面滚动，目录同步高亮当前标题。
- 所有动效在 `prefers-reduced-motion: reduce` 下关闭，并直接展示最终状态。

## 5. 核心功能设计

### 5.1 全屏动态背景

**桌面端默认：**

- 视频固定全屏，`position: fixed`、`object-fit: cover`、`z-index: -1`。
- 静音、自动播放、循环、`playsinline`。
- 视频带 `poster="/assets/bg-poster.jpg"`，不阻塞首屏文字渲染。
- 上方叠加多层暗色渐变与颗粒纹理，保证文字对比度。
- 标签页隐藏时暂停视频，返回时尝试恢复播放。

**兜底矩阵：**

| 场景 | 表现 |
| --- | --- |
| 桌面端正常环境 | 播放 `bg.mp4` |
| 屏幕宽度 ≤ 768px | 隐藏视频，显示 `bg-poster.jpg` |
| `prefers-reduced-motion: reduce` | 隐藏视频，显示静态图，关闭动效 |
| 开启省流量模式 | 隐藏视频，显示静态图 |
| 网络类型为 `slow-2g` / `2g` | 隐藏视频，显示静态图 |
| 低电量且未充电（Battery API 可用） | 隐藏视频，显示静态图 |
| 视频加载失败 | 自动切换静态图 |
| 自动播放被浏览器阻止 | 自动切换静态图 |

静态图和大尺寸视频均放在 `public/assets/`，由 Nginx 直接返回，不经过前端打包。

### 5.2 内容与 Markdown

- 使用 Astro Content Collections 读取 `src/content/blog/*.md`。
- 文件名自动作为文章 URL slug。
- 列表页自动按 `pubDate` 倒序排列。
- `draft: true` 的文章不参与构建展示。
- 支持二级、三级标题自动生成目录。
- 阅读时长按以下规则估算：
  - 中文 300 字 / 分钟
  - 英文 200 词 / 分钟
  - 最少显示 1 分钟
- 代码块在构建时通过 Shiki 高亮，主题为 `github-dark`，运行时不加载高亮库。
- 文章详情自动生成上一篇 / 下一篇。

**文章 frontmatter 规范：**

```yaml
---
title: 文章标题
description: 文章摘要
pubDate: 2026-11-03
updatedDate: 2026-11-04
category: 随笔
tags:
  - 黄昏
  - 日常
draft: false
---
```

### 5.3 阅读体验

- 正文采用 0.96—1.04rem 字号、约 2 倍行高。
- 正文最大宽度受控，避免长行阅读疲劳。
- 标题使用宋体回退，和正文形成轻微层级差。
- 引用块使用暖橙左边线与浅暖色背景。
- 行内代码与代码块分别处理，代码块保持横向滚动。
- 文章目录在桌面端固定于右侧，移动端折叠为「本页目录」。
- 顶部细线进度条显示阅读进度。

### 5.4 音乐播放器

- 页面右下角显示 56—61px 的极简黑胶唱片按钮。
- 音频文件：`public/assets/music/twilight.mp3`。
- 默认不播放，必须由用户点击触发，符合浏览器自动播放限制。
- 点击播放后：
  - 黑胶开始旋转；
  - 出现柔和的呼吸环；
  - 播放图标切换为暂停；
  - 悬停提示切换为「正在播放」。
- 音量默认约 34%，循环播放，`preload="none"`，不占用首屏带宽。
- 音频为程序生成的原创氛围曲，不使用第三方音乐版权素材。
- 音频加载失败时，按钮进入不可用视觉状态，不阻断其他页面功能。

### 5.5 响应式策略

| 宽度 | 策略 |
| --- | --- |
| ≥ 1180px | 完整双栏主视觉、右侧明信片、三列文章 |
| 1024—1179px | 收窄主视觉，三列文章自动转两列 |
| 960—1023px | 隐藏首页明信片，保留单栏主视觉 |
| 860—959px | 顶端导航切换为移动菜单 |
| 768—859px | 背景切换为静态图，阅读页目录折叠 |
| ≤ 768px | 单列文章卡片、摄影横滑、底部信息纵向排列 |
| ≤ 600px | 进一步压缩字号层次、内边距和文章间距 |

## 6. 技术方案

### 6.1 技术栈

| 层级 | 选型 | 原因 |
| --- | --- | --- |
| 框架 | Astro 7 | 默认零 JS 的静态输出，适合内容站 |
| 样式 | Tailwind CSS 4 + 自定义 CSS | 快速处理响应式，同时保留复杂视觉的可控性 |
| 内容 | Astro Content Collections | 类型安全的 Markdown 读取与校验 |
| 高亮 | Shiki | 构建时高亮，无运行时代价 |
| 脚本 | 原生 JavaScript | 菜单、目录、进度、音乐等轻交互 |
| 构建 | Vite（Astro 内置） | 快速构建与静态产物输出 |

运行环境要求：Node.js `>= 22.23.4`。

### 6.2 数据流

```text
src/content/blog/*.md
        ↓
content.config.ts 校验 frontmatter
        ↓
lib/posts.ts 排序 / 阅读时长 / slug
        ↓
Astro 页面静态生成
        ↓
dist/（HTML + CSS + 静态资源）
        ↓
阿里云 Nginx
```

### 6.3 工程结构

```text
src/
├── components/        视觉与交互组件
├── content/blog/      Markdown 文章
├── layouts/           全局页面骨架
├── lib/posts.ts       内容处理工具
├── pages/             路由页面
├── styles/global.css  Tailwind 主题与全局样式
├── config.ts          站点信息、导航、社交链接
└── content.config.ts  内容 schema
```

### 6.4 构建与部署

```bash
npm install
npm run dev
npm run build
npm run preview
```

- 构建目标：`dist/`
- 当前构建：9 个静态页面，包含 4 篇示例文章
- 当前产物：约 3.8MB，主要为背景视频、静态图和音乐
- 部署方式：将 `dist/` 内容上传至 Nginx 站点目录
- 推荐缓存：
  - `/_astro/`：一年，immutable
  - `/assets/`：7 天
  - HTML：不强制缓存，便于内容更新立即生效
- 具体 Nginx 配置根据正式域名、HTTPS 证书和服务器目录调整

## 7. 内容与素材规范

### 7.1 文章

- 使用标准 Markdown。
- 标题层级从 `##` 开始使用，最多到 `####`。
- 每篇文章必须有 `title`、`description`、`pubDate`。
- 摘要控制在一到两句话，用于列表卡片和 SEO 描述。
- 代码块标注语言，便于 Shiki 正确高亮。
- 图片使用相对路径或 `/assets/...`，并提供有意义的 alt。

### 7.2 图片

- 推荐格式：JPEG / WebP。
- 文章配图建议宽度 1280px 以内。
- 图片应事先压缩，避免直接上传相机原图。
- 装饰性背景图统一使用 `public/assets/`。
- 内容图片必须有 alt 文本。

### 7.3 背景视频

- 格式：MP4 / H.264。
- 分辨率：建议 1280×720，桌面背景无需 4K。
- 时长：5—15 秒，首尾衔接尽量自然。
- 必须静音、裁掉音轨、开启 faststart。
- 推荐控制在 2MB 以内。
- 必须同时提供静态兜底图 `bg-poster.jpg`。

### 7.4 音乐

- 格式：MP3。
- 建议 1—2 分钟，循环衔接自然。
- 默认音量不宜过大，避免访客被突然的声音惊到。
- 不使用未授权的商业音乐。
- 上线前再次确认音频资产的版权归属。

## 8. 非功能要求

### 8.1 性能目标

| 指标 | 目标 |
| --- | --- |
| 首屏关键资源（移动端） | 控制在 500KB 内 |
| 移动端背景 | 只加载约 156KB 的静态图，不加载视频 |
| 桌面背景视频 | 约 1.6MB，允许延迟播放 |
| 音频 | `preload="none"`，点击后才开始加载 |
| LCP | 生产环境 4G 下目标 ≤ 2.5s |
| CLS | 目标 < 0.1 |
| 外部依赖 | 0 个外部字体、0 个外部 CDN、0 个前端框架运行时 |

以上除实际资源体积外，均为上线后的性能目标，需要在正式域名和 Nginx 环境中复测。

### 8.2 无障碍

- 提供「跳到主要内容」链接。
- 所有可交互元素可通过键盘访问。
- 当前导航链接使用 `aria-current` 标记。
- 图片具备 alt，装饰性素材使用空 alt 或 `aria-hidden`。
- 移动端菜单支持 Esc 关闭并恢复焦点。
- 音乐按钮提供 `aria-pressed` 和可读状态文案。
- 支持 `prefers-reduced-motion`，停止背景视频和装饰动效。
- 正文、导航与按钮的对比度以 WCAG AA 为目标。

### 8.3 SEO

- 每个页面生成独立标题和描述。
- 配置 canonical、Open Graph、Twitter Card。
- 使用语义化标题层级和 `<time>` 标签。
- 提供 `robots.txt`。
- 上线前替换正式域名，验证 canonical 与分享预览。
- 站点地图与 RSS 作为第二阶段优先补充项。

### 8.4 浏览器兼容

- 目标：近两年的 Chrome、Edge、Safari、Firefox。
- 毛玻璃通过 `-webkit-backdrop-filter` 兼容 Safari。
- 不支持毛玻璃时自动使用更不透明的深色背景。
- Battery API 不可用时，仅跳过低电量判断，不影响其他功能。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 背景视频文件过大 | 首屏变慢、移动流量增加 | 移动端禁用视频；桌面视频压到 2MB 内；使用 faststart |
| 视频自动播放被拦截 | 背景空白 | 设置 poster 并监听播放失败，自动切静态图 |
| 背景过亮影响阅读 | 正文对比度不足 | 多层暗色渐变 + 半透明深色卡片 + 局部暗角 |
| 毛玻璃不兼容 | 卡片层次变弱 | 使用 `@supports` 提供不透明深色降级 |
| Battery API 不可用 | 低电量策略不触发 | 属于渐进增强，不影响基础兜底 |
| 字体在不同系统差异大 | 视觉不完全一致 | 使用稳定的中文系统字体回退栈，不依赖网络字体 |
| 素材版权不清晰 | 无法公开部署或产生纠纷 | 上线前确认背景视频、插画、照片和音乐的授权 |
| 域名未备案 | 阿里云大陆服务器无法正常访问 | 上线前完成 ICP 备案 |
| 内容更新流程单一 | 长期维护成本 | Markdown 目录规范 + 本地写作说明；后续可接 CMS |
| 范围持续扩张 | 第一期无法收口 | 评论、搜索、统计、相册等功能统一留到第二阶段 |
